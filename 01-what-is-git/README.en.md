# Topic 01 — What is Git?

## The Analogy

Imagine you are writing a school essay. You save copies like this:
- essay.docx
- essay_v2.docx
- essay_FINAL.docx
- essay_FINAL_really.docx

This gets messy fast. Git solves this problem.

## What is Git?

Git is a **version control system**. It tracks every change you make to your files.
Think of it as a time machine for your project.

- You can save a "snapshot" of your project at any point.
- You can go back to any previous snapshot.
- You can work on multiple versions at the same time (branches).
- Multiple people can work on the same project without overwriting each other.

## Key Terms (Plain English)

| Term         | Meaning                                               |
|--------------|-------------------------------------------------------|
| Repository   | A folder that Git is tracking (also called a "repo")  |
| Commit       | A saved snapshot of your project                      |
| Branch       | A separate line of work inside the same repo          |
| Merge        | Combining two branches together                       |
| Remote       | A copy of your repo stored online (e.g., GitHub)      |

## Git vs GitHub

- **Git** = the tool installed on your computer
- **GitHub** = a website that stores your Git repos online

Git can work completely offline. GitHub is optional (but very useful).
